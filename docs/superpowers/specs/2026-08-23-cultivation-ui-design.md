# 修仙挂机游戏界面设计规格

## 目标

将当前纯文字、低层级的 React 页面升级为“东方玄幻・夜色灵气”视觉界面，同时保持现有认证、心跳、状态刷新和手动突破行为不变。

## 视觉方向

- 主色：深靛蓝与墨黑，用于营造夜间修炼场景。
- 强调色：青绿色灵气，用于状态、进度和在线反馈。
- 操作色：金色，用于境界、突破和重要数值。
- 辅助色：朱红，仅用于错误提示或危险状态。
- 面板：半透明深色卡片、细边框、柔和阴影和少量背景光晕。
- 装饰：仅使用 CSS 渐变、光晕和纹理，不引入外部图片、字体或运行时资源。

## 页面结构

### 认证状态

未登录时显示居中的仙门认证卡片，包含：

- 游戏标题和简短副标题。
- 用户名、密码输入框。
- 主认证按钮。
- 登录/注册模式切换按钮。
- 错误提示条和加载状态。

### 游戏状态

登录后页面采用响应式布局：桌面端为双栏，移动端自动变为单栏。

顶部区域包含：

- 游戏名称。
- 当前用户名。
- 当前境界与层数。
- 在线/离线状态徽标。

左侧“角色属性”区域包含：

- 等级、境界、层数。
- 气血、真元、攻击、防御、速度。
- 暴击率、闪避率。

右侧“打坐修炼”区域包含：

- 当前灵气总量。
- 在线获取速度和离线获取速度。
- 当前等级灵气进度条。
- 突破需求说明。
- 手动突破按钮。

## 交互规则

- 不增加开始/停止打坐按钮，玩家始终处于挂机状态。
- 在线/离线状态只由服务端返回的 `isOnline` 决定。
- 灵气进度条使用服务端返回的 `levelProgress`，前端不自行计算成长数值。
- `breakthrough.canBreakthrough` 为真时，突破按钮使用高亮状态；否则保持禁用并显示原因。
- 认证、刷新、心跳和突破异常统一显示为页面内提示条。
- 心跳和页面焦点刷新逻辑保持现有实现。

## 技术边界

- 只修改 `apps/web/src` 下的页面、组件和样式文件，以及必要的前端测试。
- 不修改服务端 API、数据库结构、游戏规则包或 Docker 配置。
- 不新增 UI 框架、图标库或外部运行时依赖。
- 保留现有 ARIA 标签和表单可访问性语义。

## 验证标准

- 未登录状态可以正常登录和注册，错误提示不破坏布局。
- 登录后能够清晰区分等级、境界、属性、灵气进度和突破操作。
- 在线/离线徽标有明显视觉差异。
- 100% 缩放下桌面布局不发生横向溢出，窄屏下内容按单栏排列。
- 现有前端测试继续通过，并补充关键渲染状态的断言。
- `npm test`、`npm run build`、`npm run lint` 全部通过。
